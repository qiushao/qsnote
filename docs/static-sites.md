# 静态站点与发布

[教程目录](README.md) · 上一篇：[电子书与导出](ebook-export.md) · 下一篇：[自定义站点主题](site-themes.md)

QSNote 把 Markdown 文章和站点配置生成为静态 HTML。可以先在本机预览，满意后再发布；生成不需要 Node.js、Hexo 或 Jekyll。以下先创建一个“学习日志”站点。

## 1. 十分钟完成本地站点

1. 新建笔记本“学习日志”，类型选“静态站点（Pure）”。
2. 在左侧空白处右键“新建文章”。名称填“我的第一篇日志”，分类使用 `default`，标签填 `学习,Markdown`，Slug 填 `hello`，不勾选“保存为草稿”。
3. 正文输入：

```markdown
# 开始记录

今天建立了我的学习日志。

## 本周计划

- 写三篇学习笔记
- 整理一次复盘
```

4. 点击“站点配置”，在“基本信息”填写站点标题“学习日志”、描述“记录每一天的收获”、作者“小林”。本地练习可先不填域名。
5. 关闭配置窗口，点击“站点预览”。

预期结果：应用生成笔记本目录中的 `public/`，随后打开本机预览窗口。首页有文章入口，点入可阅读正文。关闭预览、修改文章、再次点击“站点预览”，即可查看新生成的版本。

配置字段修改后会保存，关闭配置窗口不表示撤销。预览无需 GitHub 或 SSH 设置，也不会上传文件；“发布站点”才会连接远端。预览使用本机 HTTP 服务，不必手工双击 `public/index.html`，尤其是配置了子路径时。

## 2. 文章属性、草稿与组织

在文章上右键“属性更改”可以修改以下内容：

| 属性 | 示例 | 用途 |
| --- | --- | --- |
| 名称 | 我的第一篇日志 | 文章标题 |
| 分类 | 学习 | 单篇文章在应用里归属一个分类 |
| 标签 | Markdown,入门 | 中英文逗号均可分隔，多标签可交叉组织 |
| SEO 关键词 | Markdown 教程,本地笔记 | 编辑已有文章时可设置；留空沿用站点关键词 |
| 日期 | 2026-10-25 | 影响文章日期、倒序排列和归档 |
| Slug | hello | 生成文章访问路径，如 `/hello/` |
| 保存为草稿 | 勾选 | 保留原稿，不进入生成站点 |

新建文章时默认带一个生成的 Slug。练习时可改为短小、不重复的英文路径，如 `markdown-basics`；同站点文章不要使用相同的 Slug，也不要占用 `tags/`、`categories/` 等站点页面路径。修改 Slug 会改变文章地址。

练习草稿：新建“未完成的想法”，勾选“保存为草稿”，写入几行内容。预览首页不会出现它；取消草稿状态，再次预览即可看到。草稿文件位于 `source/_drafts/`，正式文章位于 `source/_posts/`，两者都可能包含分类子目录。

左侧可切换“按分类”“按标签”“按日期”。多标签文章会出现在多个标签组下，仍是同一篇文章。顶部搜索匹配当前站点笔记本内的文章标题和正文；网站访客使用的是生成网页中的站内搜索。

### 分类管理

左侧右键“新建分类”，或者进入“站点配置 → 分类管理”。创建“学习”，然后在文章属性中选择它。分类管理提供新建、重命名、删除；删除分类会把文章移入 `default`，不删除文章。内置 `default` 不可重命名或删除。

## 3. 站点外观和基本信息

在“站点配置 → 基本信息”填写：

- **站点标题、站点描述、作者**：例如“学习日志”“记录每一天的收获”“小林”。
- **SEO 关键词**：例如 `学习,Markdown,笔记`，作为文章未单独设置时的默认值。
- **GitHub 地址**：填个人主页 HTTP(S) 地址，例如 `https://github.com/example-user`；这是展示链接，发布仓库在另一处配置。
- **城市**：按主题原有位置展示，不同主题可能没有对应位置。
- **头像**：点“选择图片…”，图片会复制为 `source/images/qsnote-avatar.png`。也可填写 `source` 内相对路径，如 `images/avatar.png`，或图片网址。留空使用主题默认效果；远程头像需要网络。
- **域名**：填写最终访问的完整网址，包括协议和必要的子路径。

“域名”的例子：

| 站点位置 | 示例值 |
| --- | --- |
| 网站根路径 | `https://notes.example.com/` |
| 网站子目录 | `https://example.com/notes/` |
| GitHub 用户站点 | `https://example-user.github.io/` |
| GitHub 项目站点 | `https://example-user.github.io/learning/` |

项目站点漏掉 `/learning/` 会造成资源或导航路径不对。域名字段用于生成链接，不会替你注册域名、配置 DNS 或设置服务器。

### 四种内置主题

“主题与页脚 → 站点主题”可选择 Pure、NexT、Yilia、3-Jekyll：

| 主题 | 练习 |
| --- | --- |
| Pure | 先保持默认，查看首页文章和侧栏信息 |
| NexT | 切换后预览文章目录、侧栏和搜索 |
| Yilia | 查看侧栏导航、文章列表和搜索效果 |
| 3-Jekyll | 在宽窗口查看标签栏、文章列表、正文三栏，点击标签筛选文章 |

每次切换后关闭配置窗口并重新“站点预览”。缩窄窗口可观察响应式布局。各主题使用同一批文章、分类、标签和友链；呈现位置有所不同。要改页脚，在同页填写“页脚文字”，例如“记录与分享”。自定义主题见[下一篇](site-themes.md)。

## 4. 分类、标签、归档、分页与搜索

添加几篇不同日期、不同标签的正式文章，在生成站点导航中分别访问“分类”“标签”“归档”。预期只有已发布文章参与这些列表；日期决定归档和排序。文章列表每页 10 篇，超过时出现分页导航。

在主题的搜索入口输入某篇文章标题或正文中的特有词，打开结果验证。NexT、Yilia、3-Jekyll 的搜索入口和呈现方式不同；3-Jekyll 还可使用标签按钮筛选。内置主题所需的搜索数据在生成时写入站点，无需另建搜索服务。

## 5. 友链与独立页面

在“友链”点“＋ 添加友链”，填写名称“示例站点”、地址 `https://example.com`，预览“友链”页可看到链接。修改名称或地址即可更新，点“删除”移除对应友链。

站点初始化会创建这些独立页面：

```text
source/
├── about/index.md
├── categories/index.md
├── links/index.md
└── tags/index.md
```

例如要写“关于我”，通过文章标签右键“打开路径”找到站点目录，再把 `source/about/index.md` 拖入工作区作为外部文件编辑。保留开头元数据，在其后写正文：

```markdown
---
{
  "title": "关于我",
  "layout": "about",
  "comments": false
}
---
# 关于我

这里记录我的学习笔记和项目经验。
```

保存后回到站点笔记本，重新预览，访问“关于”。独立页面不自动出现在左侧文章树中；`source/` 下其他普通 Markdown 文件也可生成独立页面。例如保存 `source/projects/index.md` 后，页面路径为 `/projects/`，内置导航不会自动增加“项目”按钮，可从正文或自定义主题链接过去。

### 进阶：手写 front matter

正常写作优先使用“文章属性”。需要细粒度控制时，可在正文最开始加入由 `---` 包围的 JSON 元数据：

```markdown
---
{
  "title": "自定义文章",
  "date": "2026-10-25",
  "categories": ["学习"],
  "tags": ["Markdown", "进阶"],
  "permalink": "advanced-note/",
  "comments": false
}
---
# 正文

这篇文章关闭评论，并使用指定访问路径。
```

正文显式包含 front matter 时，保存会保留作者原文，不再自动生成属性头；界面属性和生成页面可能因此不同。选择这种写法后，要自行维护头部字段。生成器还接受简单 YAML 的标量和列表，不支持完整 Hexo 配置语法；JSON 示例更容易保持字段类型明确。`draft: true` 或 JSON 中 `"published": false` 也会让页面被排除。

## 6. 评论

“站点配置 → 评论”可选关闭、Valine、Gitalk 或 Disqus。评论服务需另外准备账号与配置；QSNote 只把填写的配置嵌入页面，不会创建服务。

| 平台 | 要填写的字段 | 使用示例 |
| --- | --- | --- |
| 关闭 | 无 | 本地学习站点保持关闭，离线浏览正文 |
| Valine | Valine App ID、Valine App Key | 填入已有应用提供的值，预览或发布后打开正式文章底部 |
| Gitalk | GitHub 用户、评论仓库、Client ID、Client Secret | 使用已配置好的评论仓库和 OAuth 应用信息，检查文章底部登录与评论 |
| Disqus | Disqus Shortname | 填已创建站点的 shortname，例如 `my-learning-notes`；不是完整域名 |

评论用于文章页；独立页面不会因此自动增加评论。评论脚本需要网络，浏览器或服务端的域名设置也可能限制本机预览，因此应在最终访问域名下核对。手写文章 front matter 中的 `"comments": false` 可关闭该篇评论。

这些字段会进入公开 HTML，包括当前 Gitalk 实现的 Client Secret；不要填写其他用途的私密令牌。不能接受这种暴露方式时，保持评论关闭或选择符合自己部署要求的方案。

## 7. 统计和自定义代码

“站长统计 → 统计代码”接受统计平台提供的完整 HTML/JavaScript，插入所有页面的 `</body>` 前，预览时也会执行。先粘贴自己使用的平台代码，再检查生成网页源代码或平台统计结果；清空字段即关闭。

“自定义代码”有两个位置。可先用无外部依赖的例子练习：

**Head 代码**（插入 `</head>` 前）：

```html
<meta name="theme-color" content="#3567c7">
<style>
  body { scroll-behavior: smooth; }
</style>
```

**Body 底部代码**（在统计代码之后）：

```html
<script>
  console.log("学习日志页面已加载");
</script>
```

预览后检查生成文件可看到这些代码。JavaScript 要带 `<script>`，CSS 要带 `<style>`；这些内容原样进入所有主题页面，仅粘贴你理解的代码。样式效果取决于主题 DOM 和选择器。

## 8. 发布到 GitHub Pages

以下例子假设已有仓库 `example-user/learning`，实际操作时替换为自己的地址。先保证本机安装 Git，且可使用已配置的 HTTPS 凭据或 SSH 密钥访问并推送仓库。应用发布不会弹出终端密码输入。

在“生成与发布”设置：

| 字段 | 示例值 |
| --- | --- |
| 发布方式 | GitHub Pages |
| 仓库地址 | `git@github.com:example-user/learning.git` 或相应 HTTPS 仓库地址 |
| 发布分支 | `gh-pages`，留空也使用此默认值 |
| 基本信息中的域名 | `https://example-user.github.io/learning/` |

1. 使用专门存放生成结果的发布分支。发布会把该分支根目录内容更新为整站结果，保留历史并正常推送；不要选择存放其他源代码的分支。
2. 先点“站点预览”，检查图片、文章和子路径。
3. 点击“发布站点”。程序会重新生成，再提交和推送站点，同时加入 `.nojekyll`。
4. 按应用提示在仓库 `Settings → Pages` 中将发布来源设为该分支的 `/ (root)`。
5. 应用提示推送完成后，等待 GitHub 部署完成，访问最终地址检查。

“已推送”不代表远端部署已经结束。需要自定义域名时，DNS、托管服务域名设置等仍需在相应服务中配置；只改 QSNote 的“域名”字段不会完成这些步骤。

## 9. 通过 SSH SCP 上传

先准备能提供静态网页的服务器、对目标目录有写权限的部署账号，以及可用于非交互连接的 SSH 密钥或 ssh-agent。先在终端连接一次目标主机，确认主机指纹。

在“生成与发布”选择“SSH SCP”：

| 字段 | 示例值 |
| --- | --- |
| SSH 主机 | `notes.example.com`，也可用 IP 或 SSH 配置别名 |
| SSH 端口 | `22`，留空使用 22 |
| SSH 用户名 | `deploy` |
| 远程目录 | `/var/www/learning` |
| 私钥文件 | 留空用 SSH 默认配置，或填本地私钥完整路径 |
| 基本信息中的域名 | `https://notes.example.com/` |

点击“发布站点”后，程序通过 `ssh` 创建目标目录，再用 `scp` 递归上传 `public/` 中的内容。需要本机 `ssh`、`scp` 在 PATH 中，且登录无需交互输入密码。

预期结果：提示“站点已通过 SSH SCP 上传”，在最终域名可看到网站。上传会覆盖同名文件，保留远端其他文件；因此删除或改名的旧文章可能仍留在服务器，需要自行清理。远程目录必须是非根目录的绝对路径，不含空格，允许文字、数字、下划线、短横线、点和路径分隔符。网页服务、HTTPS 和域名映射由服务器侧负责。

## 10. 文件与故障排查

```text
学习日志/
├── _index.json          # 笔记本结构、文章属性和站点配置
├── source/
│   ├── _posts/          # 正式文章
│   ├── _drafts/         # 草稿，不生成
│   ├── about/index.md   # 独立页面
│   └── images/          # 例如站点头像
└── public/              # 每次生成的站点成品
```

正文图片还可能位于文章旁的 `resources/images/`。备份完整笔记本目录，不能只备份 `public/`。生成会更新整个 `public/`，不要直接在里面手工改主题或文章；需要发布的额外静态资源放到 `source/` 的普通目录。以 `_` 或 `.` 开头的路径会被排除，`_posts` 是例外。

| 问题 | 检查方法 |
| --- | --- |
| 新文章不在站点里 | 是否草稿；是否在 `_drafts`；手写 front matter 是否有 draft/published 限制 |
| 页面样式或图片丢失 | 域名子路径是否正确；本地图片是否仍存在；重新使用“站点预览” |
| front matter 报错 | JSON 是否有效、`---` 是否闭合、是否用了不支持的复杂 YAML |
| 评论或统计离线失效 | 第三方服务需要网络，检查其配置和允许域名 |
| 发布提示设置不完整 | 选择发布方式并填齐对应字段，检查本机 Git/SSH/SCP |
| Permission denied / 主机验证失败 | 在终端确认同一用户与密钥可连接，主机指纹已记录，目标有写权限 |
| Git 推送失败 | 检查凭据、仓库权限和分支保护；远端分支变化时核实后重试 |
| 发布成功却看到旧网页 | 等待托管部署，检查实际访问地址和浏览器缓存；SCP 检查远端旧文件 |

发布前检查首页、文章、分类、标签、归档、搜索和图片；发布后再访问实际网址检查一次。外部服务的设置与账号权限以服务当前界面为准。
