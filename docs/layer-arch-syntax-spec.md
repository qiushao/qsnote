## 1. 设计目标

LayerArch 是**用于分层架构图的 Markdown 扩展 DSL**，遵循五项原则：

> **标题即层级、列表即组件、缩进即嵌套、`@` 即属性、箭头即关系。**

- **可阅读**：不经过渲染也能看懂软件架构。
- **可维护**：编辑文本即可调整模块、颜色与分组；不手写坐标。
- **语义明确**：同一份源码在不同符合规范的渲染器中应产生相同的结构。
- **按需扩展**：基础架构图无需 ID、JSON、坐标或复杂的图定义。
- **专注场景**：优先覆盖多层、并排模块、嵌套容器、简单箭头；不是通用流程图语言。

规范中的 **必须** 表示符合 1.0 规范的实现需要支持；**可选** 表示实现可以额外支持但不得改变 1.0 的语义。

### 1.1 使用方式

在 Markdown 中使用自定义代码围栏：

````markdown
```layer-arch
@title 简单架构图
@theme azure

# 应用层 @color(mint)
- Web
- App

-->

# SDK @color(blue)
## 核心模块
- Sender Core
- Receiver Core

-->

# 系统层 @color(gray)
- Android
- Linux
```
````

> `layer-arch` 不是标准 Markdown 原生代码语言，需要由支持该扩展的插件或独立渲染器处理。在普通 Markdown 浏览器中，它应当按普通代码块显示，不应破坏正文。

### 1.2 本规范的层次概念

| 概念 | 语法 | 作用 |
|---|---|---|
| 图表 | 一个 `layer-arch` 代码块 | 整张图及其元信息 |
| 顶层区块 | `# ...` | 包含模块或子容器的顶层容器 |
| 模块行 | `## ...` | 顶层容器内横向排列模块的子容器 |
| 组件 | `- ...` | 一个普通模块或嵌套容器 |
| 嵌套组件 | 缩进后的 `- ...` | 表示包含关系，可递归多级 |
| 属性 | `@color(...)` 等 | 设置颜色、填充、边框和布局 |
| 整体连线 | `-->` | 相邻两个顶层区块之间的向下箭头 |

## 2. 基本语法

### 2.1 元信息

元信息位于第一个 `#` 区块之前；每行一条：

```text
@title 投屏 SDK 分层架构图
@desc Apps、SDK、操作系统的层级关系
@theme azure
@color(blue)
```

| 元信息 | 是否必填 | 说明 |
|---|---|---|
| `@title 文本` | 否 | 图的标题；可用于 SVG `<title>` 和页面标题 |
| `@desc 文本` | 否 | 图的描述；可用于 SVG `<desc>` 和无障碍描述 |
| `@theme 名称` | 否 | 图表总体视觉主题；1.0 内置 `azure`、`light`、`dark`，默认为 `azure` |
| `@color(颜色)` | 否 | 图表默认强调色，未指定时由 `@theme` 确定 |

`@title` 和 `@desc` 的值为该行剩余文本，不需要引号；`@theme` 的名称区分大小写，建议使用小写。元信息不可放在模块内部。

### 2.2 顶层区块：`#`

```markdown
# 操作系统
- Linux
- Windows
```

上例生成一个带实线边框的顶层容器，标题“操作系统”在顶部居中，Linux 和 Windows 两个模块在下方并排。直接写多个 `##` 时，每个 `##` 生成一个子容器，在顶层容器内自上而下排列。

同一个 `#` 内**不得同时**拥有直接子列表项和 `##`，否则报错；如需混排，请把模块放入某个 `##` 中。

### 2.3 模块行：`##`

```markdown
# SDK @color(blue)
## 对外 API @fill(soft)
- C API | 稳定 ABI 边界
- JNI | Android / AndroidTV

## 业务核心 @fill(solid)
- Sender Core
- Receiver Core
```

每个 `##` 在所属的 `#` 内创建一个子容器，默认使用实线边框，标题在顶部居中。`@border(dashed)` 改为虚线边框，`@border(none)` 隐藏边框。`@label(hide)` 可单独隐藏标题。

1.0 不使用 `###`、`####` 构造容器嵌套；更深层次统一使用列表缩进。

### 2.4 模块：`-`

```markdown
- QSCast
- QSCast | 私有协议 · 收发
- QSCast | 私有协议 · 收发 @color(orange) @fill(solid)
```

规则：

- `-` 后先写模块标题。
- 可以用**第一个未转义的** `|` 分隔标题与副标题。
- 副标题可以省略，分隔符两侧空白会去除。
- 行尾可以附加一个或多个属性。
- 普通模块渲染为卡片；如果其下面有缩进子列表，则自动变为**容器卡片**。

### 2.5 文本转义

在模块标题和副标题中，以下字符需要转义：

| 要显示的字符 | 源码写法 | 原因 |
|---|---|---|
| `|` | `\|` | 避免被解析为主副标题分隔符 |
| 处在属性识别位置的 `@` | `\@` | 避免被解析为行尾属性 |
| `\` | `\\` | 转义字符本身 |

例如：

```markdown
- RTP \| RTSP | 网络传输层
- 邮件地址 | 联系 foo\@example.com
```

**仅识别行尾**以空白分隔、形式为 `@属性(参数)` 的属性串。正文中的普通 `@` 并不要求转义。模块文字按**纯文本**处理，不执行嵌套 Markdown、HTML 或脚本。

## 3. 层级与容器

### 3.1 缩进即嵌套

```markdown
# 服务层
## 业务模块
- 业务集群 @border(dashed) @cols(2)
  - 服务A
  - 服务B
  - 服务C
  - 服务D
```

上例中，`业务集群` 是容器卡片，内部有四个普通模块，按两列排列。

规则：

- 列表项的直接子列表缩进**恰好增加两个空格**。
- 同一深度的列表项缩进一致；禁止 Tab 缩进。
- 子列表允许继续嵌套，无固定最大深度。
- 只有实际包含子列表的模块才渲染为容器；不需要显式 `@group`。
- 容器标题默认在顶部居中显示；可用 `@label(hide)` 隐藏。

### 3.2 容器自动判定

```markdown
- 服务A
```

→ 普通组件。

```markdown
- 集群A
  - 服务1
  - 服务2
```

→ 一个名为「集群A」的组件容器，其内部有两个普通组件。

### 3.3 三级与更多层级

```markdown
# 服务层
## 核心服务 @cols(2)
- 业务集群 @cols(2)
  - 集群A @stack
    - 服务1
    - 服务2
  - 集群B @stack
    - 服务3
    - 服务4
- 监控中心
```

视觉包含关系为：服务层（`#`）→ 核心服务行（`##`）→ 业务集群（`-`）→ 集群A/B（缩进 `-`）→ 服务1/2/3/4（进一步缩进 `-`）。

> 注意：`#`/`##` 用来表示顶层区块与其模块行；更深层级不是继续写 `###`，而是继续增加列表缩进。

## 4. 属性语法

### 4.1 统一书写规则

所有有参数的属性统一使用 `@name(value)`；无参数属性使用 `@name`。

```markdown
## 核心服务 @cols(3) @fill(solid)
- 业务集群 @color(#B5D4F4) @border(dashed) @cols(2)
- 监控中心 @stack
```

- 属性放在标题或副标题末尾；同一行多个属性以空格分隔。
- 属性名、预定义枚举值均使用小写。
- 不允许旧式 `@cols=3`、`@solid`、`@azure` 作为 1.0 正式写法。
- 同一元素上重复声明同名属性是错误；不应无提示地选用最后一个。
- 非法或未支持属性应反馈诊断，而非静默丢弃。

### 4.2 1.0 属性总表

| 属性 | 适用位置 | 功能 | 默认 |
|---|---|---|---|
| `@color(name)` | 全局、`#`、`##`、`-` | 指定颜色；支持预定义名称 | 继承父级或主题 |
| `@color(#RRGGBB)` | 同上 | 精确颜色 | 继承父级或主题 |
| `@fill(soft)` | `#`、`##`、`-` | 柔和浅色填充 | 取决于元素类型 |
| `@fill(solid)` | `#`、`##`、`-` | 标准色填充 | 普通卡片默认 |
| `@fill(none)` | `#`、`##`、`-` | 透明填充 | — |
| `@border(solid)` | `#`、`##`、`-` | 实线边框 | `solid` |
| `@border(dashed)` | 同上 | 虚线边框 | — |
| `@border(none)` | 同上 | 无边框 | — |
| `@cols(n)` | `##`、带子项的 `-` | 直接子项按 `n` 列网格布局 | 子项在同一行 |
| `@stack` | `##`、带子项的 `-` | 子项纵向排列，等价于 `@cols(1)` | — |
| `@span(n)` | `-` | 在直接父网格中横跨 `n` 列 | `1` |
| `@label(left)`、`@label(center)`、`@label(right)` | `#`、`##`、带子项的 `-` | 容器标题左对齐、居中或右对齐 | `center` |
| `@label(hide)` | 同上 | 隐藏容器标题 | — |

**约束：** `@cols(n)` 与 `@stack` 不得同时用于同一元素。`n` 为正整数。`@span(n)` 必须用于有显式 `@cols(m)` 的直接父容器/行，且 `1 ≤ n ≤ m`。`@span` 不适用于由 `#` 直接包含的模块。

### 4.3 位置合法性

- `@color`、`@fill` 支持在祖先处设置默认值，并由后代覆写。
- `@border` 作用于当前容器或卡片。容器使用 `@border(none)` 时内边距为零，子模块之间仍有间距。子组件独立使用各自的边框样式。
- `@cols`、`@stack` 仅控制**直接子项**排列，不改变孙级布局。
- `@span` 只改变该模块在**直接父网格**中的占列数。
- `@label` 只影响当前容器的标题和副标题。左、右对齐以容器的内容边缘为准。旧写法 `@label(show)` 等同于 `@label(center)`。

## 5. 颜色与样式

### 5.1 推荐使用 `@color(...)`

```markdown
# 应用层 @color(mint)
# SDK @color(blue)
# 操作系统 @color(#F1EFE8)
```

两种正式颜色形式：

1. `@color(blue)`：引用内置主题色（由渲染器提供配套文字色、边框色）。
2. `@color(#B5D4F4)`：指定准确的 **HEX RGB 六位色**，大小写均可；表示基础填充色。

1.0 **不强制支持** `rgb()`、`rgba()`、CSS 变量、alpha HEX 或渐变。非法颜色需要错误提示。

### 5.2 预定义颜色

以下为 1.0 的默认浅色主题色板，渲染器可根据 `dark` 主题调整明暗，但名称必须保留：

| 颜色名 | 基础色 HEX | 推荐用途 |
|---|---|---|
| `blue` | `#B5D4F4` | SDK、业务核心 |
| `mint` | `#E1F5EE` | Apps、入口层 |
| `purple` | `#CECBF6` | 扩展组件 |
| `orange` | `#FAEEDA` | 重点模块 |
| `slate` | `#D3DCE8` | 系统、基础设施 |
| `gray` | `#F1EFE8` | 中性背景 |
| `green` | `#C8E6C9` | 业务能力 |
| `pink` | `#F5DCE6` | 可选功能 |
| `yellow` | `#FFF1BF` | 警示、提示模块 |

### 5.3 填充层次

- `@fill(solid)`：以 `@color` 决定的基础颜色填充卡片。
- `@fill(soft)`：基础颜色与所在背景混合为更浅的填充；由渲染器采用固定混合比例（建议 35% 基础色 + 65% 背景色）。
- `@fill(none)`：透明填充，保留边框和文字。

在 HEX 模式下，`@color(#B5D4F4) @fill(solid)` 应直接使用 `#B5D4F4` 作为填充色；若使用 `@fill(soft)`，则按上述混合规则变浅。

### 5.4 样式默认值与继承

为避免“继承样式到底影响背景还是子组件”的歧义，1.0 使用下列规则：

1. `@color` 继承：图表默认色 → `#` → `##` → `-` → 嵌套 `-`，就近覆盖。
2. `@fill` 作为**后代卡片的默认填充样式**向下传递；如果当前对象是可见卡片，其自身也采用这个样式。未显式设定填充时，普通模块和嵌套容器卡片默认为 `solid`。
3. `#` 和 `##` 容器的**分组底板**使用当前颜色的浅色面板（独立于普通模块卡片的 `fill`）；因此即使模块使用 `solid`，外层 SDK 容器仍可保持浅色背景。
4. `@border` **只作用于当前对象**，不继承；`#`、`##` 容器和 `-` 卡片均默认使用实线边框。
5. `@label` 不继承。

示例：

```markdown
# SDK @color(blue)
## 对外 API @fill(soft)
- C API
- JNI
## 业务核心 @fill(solid)
- Sender Core
- Receiver Core
- QSCast @color(orange)
```

所有 API 模块为柔和蓝色，业务核心模块为标准蓝色，只有 QSCast 是橙色。

### 5.5 可读性

渲染器应当自动选择可读的文字颜色与边框颜色；建议正文对比度不低于 WCAG AA 的 4.5:1。不可因纯白 `@color(#ffffff)` 导致白字或不可见边框。

## 6. 布局与自动排版

### 6.1 基本方向

- 顶层 `#` 区块自上而下堆叠。
- `#` 直接包含的模块默认横向等宽排列。
- `#` 内的 `##` 子容器自上而下排列，每个子容器内的模块默认横向等宽排列。
- 嵌套 `-` 容器内部的直接子项，未标注布局时，默认横向等宽排列。
- 自动测量文字尺寸、处理换行；不能用固定像素坐标作为源码语法。

### 6.2 列数与纵向堆叠

```markdown
## 协议插件 @cols(2)
- QSCast
- Miracast
- AirPlay
- DLNA
```

四个模块按照两列、两行排列，采用**按行优先**（row-major）顺序。缺省时四个模块排在同一行。

```markdown
- 监控与保护 @stack
  - Sleuth
  - Turbine
  - Hystrix
```

三个子组件按纵向排列。

### 6.3 跨列

```markdown
- 核心业务 @cols(2)
  - Zuul
  - Zuul
  - 业务集群 @span(2) @cols(2) @border(dashed)
    - 服务A
    - 服务B
    - 服务A
    - 服务B
```

`业务集群` 在父容器的两列网格中**横跨两列**；业务集群内部又是一个独立的两列网格。

### 6.4 自适应策略

- 节点宽度取所在网格的等分宽度，`@span(n)` 按实际占列数扩展。
- SVG `viewBox` 应包围全部内容，不能裁剪文本；宽度随容器自适应。
- 文本换行优先于溢出；当容器过窄时允许页面水平滚动，而不是压缩到不可读。
- 嵌套级别加深时自动增高父容器。
- 1.0 不承诺与某张参考图像素级一致；左侧梯形标签、数据库圆柱体等图形不在基础语法范围。

## 7. 连接线

### 7.1 顶层整体连接

仅在两个**相邻顶层区块**之间，单独一行写：

```markdown
# 应用层
- App

-->

# SDK
## 核心
- Core

-->

# 系统层
- Android
```

语义：上一顶层区块的底部中心，连到下一顶层区块顶部中心，绘制一条有箭头的向下连线。

- `-->` 不能写在嵌套列表内部。
- 不能放在第一个顶层区块之前或最后一个区块之后。
- 两个连续 `-->` 是语法错误。
- 未写 `-->` 的相邻区块仅做垂直布局，**不自动添加箭头**。
- 1.0 不要求支持模块到模块的指定连线；此能力预留给 1.1。

### 7.2 后续兼容预留（非 1.0）

未来可扩展：

```text
- Sender Core @id(sender)
- QSCast @id(qscast)
@link(sender,qscast)
```

`@id` 和 `@link` **只是未来可能的提案**，1.0 实现不得把它们当成已定义的标准语法。

## 8. 解析、校验与兼容

### 8.1 建议的简化语法

以下是结构性描述，非完整词法 EBNF：

```text
document    := preamble? topBlock (connector? topBlock)*
preamble    := (title | desc | theme | globalColor)*
topBlock    := heading1 (directItems | heading2Block+)
heading2Block := heading2 nestedItem+
directItems := nestedItem+
nestedItem  := indent '- ' title (' | ' subtitle)? attrs? newline
               (childItem*)
childItem   := nestedItem with indent exactly parentIndent + 2 spaces
connector   := '-->' on a standalone, unindented line
attrs       := (' ' '@' name '(' value ')')* | (' ' '@stack')*
```

**更精确的约束**：一个 `#` 区块的直接子元素必须**全部是 `-` 或全部是 `##`**；`##` 内必须有至少一个直接子列表项；一个嵌套 `-` 可以有零个或多个下一深度子项。

### 8.2 建议的处理顺序

1. 从普通 Markdown 中识别 `layer-arch` fenced code block。
2. 将源内容按 UTF-8 行解析，识别元信息、标题、箭头、列表与缩进。
3. 从每行末尾解析属性，再解析标题/副标题。
4. 建立 AST：`Diagram`、`TopBlock`、`Row`、`Node`、`Connector`。
5. 校验属性、颜色、缩进、`@span`、互斥结构等。
6. 进行样式解析和层级布局。
7. 生成带 `<title>`、`<desc>` 的安全 SVG。

### 8.3 错误处理

| 错误代码（建议） | 错误示例 | 处理建议 |
|---|---|---|
| `E001` | `##` 出现在任何 `#` 前 | 报告行号和位置 |
| `E002` | 一个 `#` 混用直接 `-` 和 `##` | 提示将 `-` 移至 `##` 下 |
| `E003` | 缩进使用 Tab 或跳过一个层级 | 提示每级两个空格 |
| `E004` | `@color(#12XX56)` | 报告非法 HEX 值 |
| `E005` | 同时使用 `@stack` 与 `@cols(2)` | 提示选择一种布局 |
| `E006` | `@span(3)` 出现在父 `@cols(2)` 中 | 提示跨度不能大于列数 |
| `E007` | `-->` 没有相邻的两个顶层区块 | 提示连接位置 |
| `E008` | 未知属性 `@colour(blue)` | 列出可能的正确属性 |
| `E009` | `-` 或 `##` 没有标题/子项 | 报告缺少结构内容 |

建议编辑器支持行号、错误下划线和分段预览；语法错误时不得注入 HTML，也不要静默渲染成错误结构。

### 8.4 兼容性与安全

- 不支持 LayerArch 的 Markdown 平台仍应保留源码代码块。
- 渲染器必须将用户文本作为纯文本节点插入 SVG；不得将用户文本当作 HTML 标签、SVG 属性或脚本执行。
- 不要求网络字体、外部 CDN 或在线服务；适合离线文档和 Git 仓库。
- 输出格式建议支持 SVG；PNG 是可选的图像导出功能。
- 中文、英文、Unicode 中点等符号均应正常支持。

# 展现层 @color(blue)
- Web | HTML · HTML5 · Vue
- App | iOS · Android
- 微信公众号 / 小程序
- RESTful 接口

# 通讯层 @color(purple)

- SLB
- Netty
- Socket

# 服务层 @color(blue)

## 核心服务 @cols(3)
- 监控与保护 @stack @color(blue)
  - Sleuth | 链路跟踪
  - Turbine | 集群监控
  - Hystrix | 容错保护

  - Zuul @color(orange)

## 11. 实现建议与版本边界

### 11.1 推荐的内部数据模型

```text
Diagram { title, desc, theme, defaultColor, blocks[] }
TopBlock { title, style, mode: row|group, rows[] | nodes[] }
Row { title, style, layout, nodes[] }
Node { title, subtitle?, style, layout?, span?, children[] }
Connector { from: previousTopBlock, to: nextTopBlock }
```

模块没有强制 `id`；内部可使用其在 AST 中的结构路径作为渲染键，但不能把路径对外当成稳定模块标识符。

### 11.2 SVG 渲染约定

- 图表标题写入 `<title>`，描述写入 `<desc>`。
- `#`、`##` 容器和模块卡片均使用圆角矩形。容器标题默认在顶部居中显示。
- 深层列表创建嵌套矩形框，子节点按网格排列。
- 顶层 `-->` 在两个区块之间绘制箭头；默认居中。
- 布局由文本测量、内边距、行间距和内容尺寸计算，不应要求用户指定像素坐标。

### 11.3 版本边界

**LayerArch 1.0 正式支持：**

- `@title`、`@desc`、`@theme`、全局 `@color`；
- `#`、`##`、`-`、`|`、`-->`；
- 缩进容器、`@color`、`@fill`、`@border`、`@cols`、`@stack`、`@span`、`@label`；
- 预定义颜色名和 `#RRGGBB`；
- 自动布局和 SVG 输出。

**本次不纳入 1.0：** 指定模块 ID、跨层任意连线、流程图条件分支、数据结构表格、数据库圆柱图形、箭头标签、图片和图标嵌入、HTML 属性注入、自定义 JavaScript、精确坐标布局。后续可以采用向后兼容的属性形式增加。

### 11.4 与早期 DSL 的关系

早期曾讨论 `layer ... / group ... / end` 与 JSON 两种方案。**本规范选择 Markdown 风格语法作为 LayerArch 1.0 的主格式**，不将旧方案纳入同一语法解析器；如需迁移，可编写单独转换工具。以免多套语法并存导致歧义。

## 12. 速查表

| 想做什么 | 怎么写 |
|---|---|
| 设置图表标题 | `@title 系统架构图` |
| 设置图表说明 | `@desc 系统分层与模块关系` |
| 设置总体主题 | `@theme azure` |
| 指定颜色 | `@color(blue)`、`@color(#B5D4F4)` |
| 新建顶层区块 | `# SDK` |
| 新建区块内模块行 | `## 业务核心` |
| 新建模块 | `- QSCast` |
| 新建带副标题模块 | `- QSCast \| 私有协议` |
| 新建嵌套容器 | `- 业务集群`，下一行缩进 `  - 服务A` |
| 设置当前行/容器为两列 | `@cols(2)` |
| 让子模块纵向堆叠 | `@stack` |
| 当前模块横跨父网格两列 | `@span(2)` |
| 设置虚线边框 | `@border(dashed)` |
| 设置浅色卡片 | `@fill(soft)` |
| 隐藏容器标题 | `@label(hide)` |
| 连接相邻两个顶层区块 | 两个 `#` 区块之间单独一行 `-->` |

**一句话总结**：LayerArch 1.0 使用 Markdown 负责结构、缩进负责包含关系、`@属性(值)` 负责表现和布局、`-->` 负责简单连接；SVG 的尺寸与坐标全部交给渲染器。
